## Read the design directive first

The QoL items below are the vehicle through which the new aesthetic enters the app. The library views especially — that's where the design gets to breathe, where a user spends time choosing what to watch. The design directive gives you the values and the vocabulary. The items give you the surfaces.

## 1. Session resume position (bug)

**The problem:** When a user closes a session and reopens it later, playback starts from the beginning instead of where they left off. The sync is saved correctly, the playback position (`lastReactionTimeSeconds`) is persisted in the session store, and the library UI shows the saved position. But the player doesn't restore it on open.

**The fix:** The position is already saved. The player just isn't reading it on session open. Find where the session loads and ensure `lastReactionTimeSeconds` is passed to the SyncController's `loadSession` call.

## 2. Entry-experience overhaul

Two coupled improvements to the "paste a link" to "I'm watching" flow. This is the first impression — it should feel like one continuous motion.

### 2a. Download progress (honest, polished)

**Patreon:** patreon-dl emits log lines, not parseable percentages. The current UI shows `percent: null`, the progress bar vanishes, and the user sees a spinner and shifting text. That reads as broken. Replace with an indeterminate progress indicator that communicates phase and motion without lying about percentage. The data we have is "which stage am I in" — show that honestly.

**YouTube:** yt-dlp gives us real percentages and can surface speed, ETA, and fragment counts via `--progress-template`. Show the user a real progress bar with context: "47% — 4.2 MB/s — 2 min left." The data is there; surface it.

### 2b. Autosync roll-in

Remove the "download complete, press sync now" interstitial. After the reaction download completes, roll straight into autosync so the ~30s detection feels like the tail of the download weight, not a separate gate. One continuous motion: download → finding sync → player opens already synchronized. The user never clicks a "start sync" button.

## 3. Auto-name pairings

Session titles currently default to the movie filename. The metadata is already there — patreon-dl downloads channel name and post title; yt-dlp can emit similar metadata. Generate session titles as "Movie Title — Reactor Name" from the available metadata. Fall back gracefully to the filename when metadata is unavailable.

## 4. Three library views (headline feature)

This is the QoL centerpiece. Once a library grows past ~10 pairings, a flat grid stops serving discovery. Build three views:

- **Pairings** (current) — the flat grid of movie + reactor combinations
- **By Reactor** — grouped by creator, showing all their available pairings
- **By Movie** — grouped by movie, showing all reactor options for each

A view toggle in the library header. The grouping is derivable from existing session data (`reactionPath` carries channel identity, `moviePath` carries movie identity). No new IPC, no new backend, no new session-model fields. Pure renderer work.

**Reactor profile pictures:** patreon-dl already downloads `avatar.jpg`. yt-dlp can grab channel thumbnails. Faces make the "by reactor" view genuinely better — humans navigate by faces. Wire in the profile pictures where they're available; fall back gracefully where they're not.
