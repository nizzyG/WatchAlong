## From the Creative Director, 2026-07-13

1. **Start reaction video while autosync runs in background.** Currently the user waits for the scan before playback. Letting them start watching while detection continues would reduce perceived latency.

2. **Name pairings based on movie + channel name.** Auto-generate session titles from the reaction metadata (movie title + reactor channel) instead of defaulting to the filename.

3. **Three library views:**
   - a. **Movie-Reactor pairings** (current view)
   - b. **By Reactor** (new) — shows all pairings available from each reactor
   - c. **By Movie** (new) — shows all reactor pairings available for each movie

4. **Letterboxd integration** to support the new library views. If you provide a link to a reactor's Letterboxd page, the library could suggest pairings for movies in your library with reactors you're subscribed to. (Creative Director doesn't use it personally, but notes many reactors do.)

5. **Companion Android/Apple app** (possibly v1.2). Catch the stream over local WiFi so you can watch from phone/tablet/TV. Needs its own versioning. The codebase may already be set up to handle this.

6. **Bug Fix — session resume position.** The sync is saved when you close a session, and the UI shows where you were in the reaction. But when you reopen a previously closed session, it starts from the beginning. The sync saves but the playback position does not restore.

7. **Reactor profile pictures in library views.** Patreon-dl downloads metadata including a profile picture. Can yt-dlp do the same? If so, include reactor images in the new library views. If not, ensure patreon-dl downloads are cleaned up to leave just the video file.

8. **Full rewrite of public-facing documentation** by the Senior Coordinator. Double down on legality by doubling down on media ownership over streaming licenses, and on supporting content creators by paying for Patreon subscriptions.
